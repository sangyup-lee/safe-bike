# Safe Bike Seoul

Next.js + TypeScript 기반 서울 자전거 지도 데모입니다.

## 통합 화면과 경로 비교

- 상단 통합 요약, 지도, 두 경로 비교표, 사고·날씨 카드, 기준시각·출처 표를 한 페이지에 배치했습니다. 대여소와 목적지를 선택하면 지도·경로 비교·날씨·사고 근접 분석이 같은 선택 상태를 사용합니다. 날씨는 한 번만 조회해 카드와 요약·출처 표가 같은 자료를 표시합니다.
- 자전거도로 우선/최단 경로의 **거리(m), 예상 소요시간, 주변 사고다발지역 수, API 조회시각**을 나란히 비교합니다. 같은 사고 기준연도와 근접 범위(100m/300m/500m/1km)를 두 경로에 공통 적용합니다. 주변 수는 과거 사고 ‘건수’나 현재 위험도가 아니라 조건 내 ‘다발지역 지점 수’입니다.
- 사고자료가 미조회/실패이거나 경로가 없으면 수를 0으로 만들지 않고 대기/확인 불가로 표시합니다. 실제 빈 자료가 확인된 경우에만 0곳입니다. 경로 하나가 실패해도 다른 경로의 실제 결과는 유지합니다.
- 경로 선택은 지도 선과 표시할 주변 사고 지점을 바꾸며, 비교 결과를 바탕으로 안전 점수·안전 순위·추천 안전 경로를 만들지 않습니다. 상단과 비교표에 실제 안전성을 판정/보증하지 않는다는 설명을 표시합니다.
- 정보 기준시각·출처 표는 아래의 차이를 명시합니다. 모든 시각은 날짜를 포함한 KST이며 서버 조회시각은 제공처 측정시각으로 부르지 않습니다.

| 정보 | 자료 기준 | 조회시각·출처 |
| --- | --- | --- |
| 따릉이 | 제공처 측정시각 미제공, 수량은 현장과 다를 수 있음 | 서울시 전체 응답을 수신한 시각 · 서울 열린데이터광장 |
| 경로 | API가 산출한 거리·예상시간, 실제 주행 측정값 아님 | 옵션별 API 응답 조회시각 · 카카오맵 |
| 사고 | 사고 발생 기준연도의 과거 연간 통계 | 통계 데이터 조회시각 · 한국도로교통공단 TAAS |
| 날씨 | 발표시각과 예보 대상시각을 각각 표기, 실황 아님 | 예보 데이터 수신 시각 · 기상청 |

- 재고 API는 `observedAt: null`, `measurementTimeProvided: false`로 측정시각 미제공을 명시합니다. 경로 API는 `timeType: server-retrieval`과 출처 URL을 반환하고 UI에서 옵션별 조회시각을 유지합니다.
- 기존 서울시 HTTP 키 전송 승인 대기 상태는 유지합니다. 연결되지 않은 재고나 선택하지 않은 대여소의 경로를 임의 자료로 채우지 않습니다.

## 실행

```powershell
npm.cmd install
npm.cmd run dev
```

현재 카카오 SDK에 등록된 주소인 http://localhost:3000 으로 접속합니다. `127.0.0.1:3000`은 별도 도메인 등록 전까지 SDK 인증이 거절됩니다.

## 카카오 지도

프로젝트 루트의 `.env`에 JavaScript SDK 키를 설정합니다. 다른 서비스 키나 REST API 키를 브라우저에 전달하지 마세요.

```dotenv
NEXT_PUBLIC_KAKAO_JS_KEY=your_javascript_key
```

Kakao Developers에서 해당 키의 JavaScript SDK 도메인에 실제 접속 주소(예: `http://localhost:3000`, `http://127.0.0.1:3000`)를 등록하고 지도 API 사용 설정을 확인하세요. 키 변경 후 서버를 재시작합니다.

공식 가이드: https://apis.map.kakao.com/web/guide/

SDK는 `autoload=false`로 로드한 뒤 `kakao.maps.load`에서 초기화합니다. CustomOverlay로 실제 대여소 좌표와 대수를, Polyline으로 카카오 자전거 경로 API의 구간 좌표만 표시합니다. 키가 없거나 SDK 연결이 실패하면 오류 안내를 표시합니다. 대여소 목록과 경로 조회는 지도 SDK 연결과 독립적으로 동작합니다.

배포 절차와 환경변수·카카오 도메인 설정은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.

경로 조회가 완료되면 지도 아래의 **경로 결과 요약**에 대여소·목적지, 두 경로의 거리·예상 시간·거리 차이, 과거 사고다발지역 근접 집계와 조회시각을 문장으로 표시합니다. 지도 경로 선택 및 근접 거리 기준을 바꾸면 요약도 갱신됩니다. 외부 생성형 AI 호출이나 추가 인증키 없이 실제 응답값으로 작성하며, 조회 실패는 수치나 경로를 만들어 대체하지 않습니다.

## 데이터 범위

- 장소 검색은 카카오 Local API의 실제 검색 결과를 사용합니다. 빈 결과와 인증 오류를 구분합니다.
- 경로·거리·시간은 카카오 공식 자전거 경로 API 응답만 사용합니다. 기존 시연용 곡선과 거리·시간 추정 함수, 가상 자전거도로 비율은 제거했습니다.
- 따릉이 가상 데이터는 제거했습니다. 대여소는 항상 서울시 bikeList에서 조회하며 실제 응답이 없으면 오류를 표시합니다.
- 사고정보는 한국도로교통공단의 실제 과거 연간 사고다발지역 통계입니다. 가상 주의 지점은 제거했습니다.
- 날씨는 기상청 실제 단기예보입니다. 가상 날씨와 초단기실황 기반 구현은 제거했습니다.
- 실제 주행 안내나 대여 가능 여부 판단에 사용하지 마세요.

`src/lib/demo-data.ts`에서 초기 출발·도착 좌표와 장소 타입을, `src/components/bike-map.tsx`에서 SDK 연동을 관리합니다.

## 백엔드 API Route

Next.js App Router의 `src/app/api/**/route.ts`에서 GET 요청을 처리합니다. 설정 모드는 URL에서 바꿀 수 없습니다.

| API | 요청 예시 | 실제 데이터 모드의 제공처 |
| --- | --- | --- |
| 장소 검색 | `/api/places?q=여의도&page=1` | 카카오 Local REST API, 서울 경계 내 검색 |
| 대여소 | `/api/stations?lat=37.5284&lng=126.9346&radius=2000&minBikes=0&limit=30` | 항상 서울 열린데이터광장 bikeList 실제 조회 |
| 날씨 | `/api/weather?lat=37.5284&lng=126.9346` | 항상 기상청 단기예보, 서버에서 출발지 좌표를 격자로 변환 |
| 사고정보 | `/api/accidents` 또는 `/api/accidents?year=2025&district=560` | 항상 한국도로교통공단 자전거 사고다발지역, 기본 서울 전체 |
| 자전거 경로 | `/api/routes?stationId=ST-실제ID&startLat=대여소위도&startLng=대여소경도&endLat=목적지위도&endLng=목적지경도&route_mode=BIKE_ONLY` | 항상 카카오 공식 자전거 경로 API |

성공 응답은 `{ data, meta: { source, isDemo, fetchedAt, ... } }`, 오류 응답은 `{ error: { code, message } }` 형식입니다. 잘못된 입력은 400, 미설정 서비스는 503, 외부 서비스 실패는 502, 경로 탐색 결과 없음은 422, 카카오 요청 한도 초과는 429입니다. 모든 응답은 `Cache-Control: no-store`를 사용합니다. 지원하지 않는 메서드는 405입니다.

모든 API는 실제 데이터만 취급합니다. `DATA_MODE`는 사용하지 않습니다. 실패한 요청을 예시 데이터로 대체하지 않습니다.

### 출발지 단기예보

- `getVilageFcst`를 사용해 같은 **예보 대상시각**의 `TMP`(기온, °C)와 `POP`(강수확률, %)를 묶습니다. 강수확률을 제공하지 않는 초단기실황 `getUltraSrtNcst`와 혼합하지 않습니다. 실제 관측 현재 기온으로 표시하지 않습니다.
- [기상청 공식 격자 명세](https://apihub.kma.go.kr/getAttachFile.do?fileName=%2820240305%29%EB%8F%99%EB%84%A4%EC%98%88%EB%B3%B4+%EA%B2%A9%EC%9E%90%EC%98%81%EC%97%AD+%EC%A0%95%EB%B3%B4.pdf)의 Lambert conformal conic 투영을 구현합니다. 지구 반경 6371.00877km, 격자 간격 5km, 표준위도 30°/60°, 기준 위·경도 38°N/126°E, 기준 격자 43/136입니다. 여의도 한강공원은 (59,126), 서울시청은 (60,127)로 변환됩니다.
- 출발지 변경 시 위·경도를 `/api/weather`로 보내며 서버가 `nx/ny`로 변환합니다. 선택한 대여소가 있으면 실제 경로 출발 대여소 좌표를 사용합니다. 변경 전 응답은 숨기고 이전 요청을 취소해 다른 출발지의 날씨가 섞이지 않도록 합니다.
- 단기예보 발표 주기인 02·05·08·11·14·17·20·23시(KST)를 사용합니다. 앱은 발표 후 10분의 제공 유예 시간을 둡니다. 새벽 첫 발표 전에는 전날 23시 자료를 선택하며 월·연도 변경도 KST 기준으로 처리합니다.
- 기상청이 명시적으로 자료 없음(`03`/빈 자료)을 반환한 경우에만 한 차례 이전 발표의 **실제 예보**를 조회하고 화면에 이를 안내합니다. 인증/연결/형식/부분 페이지 오류를 오래된 값으로 숨기지 않습니다.
- 1,000개씩 전체 페이지를 받아 발표시각과 격자가 일치하는지 검증합니다. 같은 예보시각에 기온·강수확률이 모두 있는 자료 중 현재 이후 가장 가까운 시각을 선택합니다. 0°C·0%는 유효한 값이고 결측값(-999 등)은 표시하지 않습니다. 과거 예보를 현재 값으로 재표시하지 않습니다.
- API의 `baseDate/baseTime/issuedAt`는 **발표시각**, `current.forecastDate/forecastTime/forecastAt`는 **예보 대상시각**입니다. 화면에 각각 날짜와 시각을 KST로 표시하고 의미를 설명합니다. 조회 시각(`meta.fetchedAt`)도 별도로 표시합니다.
- 서버는 격자·발표회차별로 자료를 10분 메모리 캐시하고 동시 요청을 합칩니다. 캐시가 있어도 표시할 예보시각은 요청 시점에 다시 고릅니다. 화면은 5분마다 재조회하며 API 실패 시 임의 기온·확률을 만들지 않습니다.
- 실제 API 검증 예: 2026-11-19 17:00 KST 발표, 같은 날 18:00 KST 예보의 여의도 격자 (59,126)에서 **기온 2°C, 강수확률 20%**를 확인했습니다. 검증 결과는 고정 예시 화면으로 사용하지 않습니다.

### 과거 자전거 사고다발지역과 경로 근접 분석

- 2026-11-19에 [공식 제공기관 문서](https://opendata.koroad.or.kr/api/selectBicycleDataSet.do)의 자료조회 가능기간 **2012~2025년**을 확인하고, 공공데이터포털 HTTPS API의 **2025년 서울 전체 110개 지점**을 실제 조회했습니다. 2025년을 최신 확인 연도로 명시하며 현재 연도에서 임의로 추정하거나 지점이 없다는 이유로 다른 연도로 조용히 바꾸지 않습니다. 향후 자료가 공개되면 `src/lib/accidents.ts`의 최신 확인 연도와 확인일을 공식 문서/실제 응답 확인 후 갱신해야 합니다.
- 서버는 `DATA_GO_KR_API_KEY`를 이용해 `https://apis.data.go.kr/B552061/frequentzoneBicycle/getRestFrequentzoneBicycle`을 호출합니다. 서울 전체 조회는 `siDo=11`, 빈 `guGun`입니다. 100개 단위 페이지를 모두 모아 `totalCount`와 수신 건수를 검증합니다. 중복·부분 실패·전체 건수 변경은 오류로 처리합니다.
- `/api/accidents`는 기본 2025년 서울 전체를 반환합니다. `year`는 2012~최신 확인 연도, `district`는 서울시 3자리 코드입니다. `page`를 클라이언트에 노출하지 않고 서버가 전체를 수집합니다.
- 중심점 마커와 API의 `geom_json` Polygon을 표시합니다. 제공되지 않은 영역을 임의 원으로 생성하지 않습니다. 마커/목록 선택 시 위치, 사고 건수, 사상자·사망·중상자 수와 사고 기준연도를 보여줍니다. 지도 경고 아이콘 버튼으로 조건에 맞는 사고다발지역 전체를 볼 수 있습니다.
- 선택한 자전거 경로의 각 실제 선분과 다발지역 **중심점** 사이의 구면상 직선 최단거리를 계산합니다. 경로 꼭짓점 거리만 사용하거나 서로 떨어진 경로 구간 사이에 가상 연결선을 만들지 않습니다. 폴리곤 경계와의 거리나 실제 접근 경로/도로 위험도 분석은 아닙니다.
- 근접 기준은 100m/300m/500m/1km, 기본 300m입니다. 가까운 지점은 다른 색으로 강조하고 거리순으로 정렬합니다. ‘경로 주변만’을 켜면 지도와 목록이 같은 지점을 표시합니다. 목록은 상위 10곳, 지도는 조건에 맞는 전체 지점입니다. 경로가 없으면 근접 분석을 하지 않습니다.
- 모든 화면에 **과거 연간 사고 통계이며 실시간 사고·현재 위험도·안전도 정보가 아님**을 안내합니다. 특정 거리 내 지점이 없다는 사실을 안전 판정으로 표현하지 않습니다. 사고 기준연도·제공연도 확인일·데이터 조회일을 구분하고 한국도로교통공단 TAAS 출처 링크를 표시합니다.
- 서버 캐시는 1시간이며 동시 요청을 합칩니다. 외부 요청 타임아웃은 15초입니다. 인증·활용 승인 실패나 연결/응답 오류 시 오류 메시지만 표시하며 가상 사고 지점으로 대체하지 않습니다.
- 실제 서울 카카오 자전거 경로(여의도~반포 공개 공원 좌표)를 이용한 통합 검증에서 7,022m 경로와 300m 이내 사고다발지역 2곳을 확인했습니다. 테스트용 출발 좌표는 실제 대여소 선택을 뜻하지 않으며 화면에 테스트 경로를 주입하지 않습니다.

### 선택한 대여소에서 목적지까지 자전거 경로

- 공식 엔드포인트는 `GET https://dapi.kakao.com/v2/routing/bicycle`입니다. 서버가 `KAKAO_REST_API_KEY`를 Authorization 헤더로 전달합니다. 카카오모빌리티 자동차 길찾기나 비공식 API로 대체하지 않습니다.
- 대여소를 선택하면 그 대여소의 좌표를 출발점으로 사용해 `BIKE_ONLY`(자전거도로 우선)와 `SHORTEST`(최단 경로)를 각각 조회합니다. 목적지/대여소 변경 시 이전 요청을 취소하고 이전 경로를 지도에서 제거합니다. 탭으로 표시할 경로를 선택하며 거리·시간을 비교할 수 있습니다.
- 응답의 `status=OK`, `route.properties.totalDistance/totalTime`, `route.legs[].steps[].path.points`를 검증합니다. WGS84 좌표 `[경도, 위도]`를 지도 좌표로 변환하며 구간 사이를 임의 선으로 연결하거나 좌표를 보간하지 않습니다.
- 실패한 옵션은 이유를 표시합니다. 인증/권한 실패, 한도 초과, 연결 실패, 동일 좌표, 도로 연결 실패, 너무 먼 거리, 경로 없음, 응답 형식 오류를 구분합니다. 실패 시 경로·거리·시간·비율을 생성하지 않습니다. 한 옵션만 성공하면 해당 옵션의 실제 응답만 사용할 수 있습니다.
- 카카오가 반환한 `landingUrl` 중 `https://map.kakao.com` 주소만 경로 열기 링크로 사용합니다.
- API는 클라이언트가 전달한 대여소 ID/좌표 형식을 검증합니다. UI는 실제 `/api/stations` 목록의 선택값만 전달합니다. ID와 좌표의 서울시 원본 일치 여부를 이 경로 API에서 재조회하지는 않습니다.
- 최초 권한 검증과 로컬 API 통합 검증은 공식 문서의 예제 좌표로 수행했습니다. `BIKE_ONLY`: HTTP 200, 4,716m, 1,139초. `SHORTEST`: HTTP 200, 4,042m, 1,221초. 이는 선택한 실제 따릉이 대여소를 사용한 종단 간 검증과 구분됩니다.

### 출발지 주변 대여소

- 출발지 선택·교환 시 해당 좌표로 자동 조회합니다. 반경 500m/1km/2km/5km, 이름 검색, 대여 가능(1대 이상) 필터를 지원합니다.
- 서울시 API의 1회 최대 1,000개 단위로 전체 페이지를 모은 뒤 Haversine 직선거리를 계산합니다. 첫 페이지만 정렬하거나 API 순서를 거리순으로 간주하지 않습니다.
- 거리 오름차순으로 최대 30곳을 목록·지도에 같은 순서로 제공합니다. 마커에는 대여 가능 대수가 표시되며 목록이나 마커 선택 시 지도 중심을 해당 대여소로 이동합니다.
- `radius`는 미터(100~10,000), `minBikes`는 0~100, `limit`는 1~100, `q`는 대여소 이름입니다. 서울 지역 위·경도는 필수입니다.
- 서버는 전체 응답을 메모리에 60초 캐시하고 동시 갱신 요청을 합칩니다. UI는 60초마다 조회하며 갱신 시각(KST)을 표시합니다. 브라우저 응답은 계속 `no-store`입니다.
- 좌표가 없거나 유효하지 않은 행을 제외하고 ID로 중복 제거합니다. 전체 페이지 중 일부가 실패하면 불완전한 결과를 반환하지 않습니다. 실패 시 이전 수량을 현재 수량으로 표시하거나 가상 대여소로 대체하지 않습니다.
- 직선거리는 도보 경로/시간이 아닙니다. 거치대 수가 제공되지 않으면 임의 숫자를 만들지 않습니다.

## 인증키 관리

처음 설정하는 환경에서는 `.env.example`을 `.env`로 복사한 뒤 실제 값을 입력합니다. 현재 작업 환경의 `.env`는 기존 키를 이용해 이미 구성되어 있습니다.

```dotenv
DATA_MODE=demo
SEOUL_ALLOW_HTTP=false
SEOUL_API_KEY=서울시_인증키
DATA_GO_KR_API_KEY=공공데이터포털_인증키
KAKAO_REST_API_KEY=카카오_REST_API_키
NEXT_PUBLIC_KAKAO_JS_KEY=카카오_JavaScript_키
```

- `SEOUL_API_KEY`, `DATA_GO_KR_API_KEY`, `KAKAO_REST_API_KEY`는 `src/server/env.ts`에서만 읽습니다. 서버 모듈에 `import "server-only"`를 적용해 Client Component에서 가져오면 빌드가 실패하게 했습니다.
- 서버용 키에 `NEXT_PUBLIC_` 접두사를 붙이거나 `next.config.ts`의 `env` 설정으로 내보내지 마세요. 서버 키를 props, API 응답, 브라우저 요청 URL에 넣지 않습니다.
- 브라우저는 같은 출처의 `/api/...`를 호출하고 서버가 정해진 제공처에만 요청합니다. 클라이언트가 임의 URL·인증키·호스트를 지정할 수 없습니다. 타임아웃은 일반 API 8초/경로 API 12초/사고·날씨 API 15초이며 리다이렉트를 따라가지 않습니다. 오류 원문이나 키가 들어 있는 외부 요청 URL을 기록하거나 반환하지 않습니다.
- 공공데이터포털 키는 인코딩/디코딩된 형식 모두 수용하며 요청 시 한 번만 인코딩합니다. 각 서비스 활용신청 승인이 필요합니다.
- `NEXT_PUBLIC_KAKAO_JS_KEY`는 지도 SDK가 브라우저에서 사용해야 하는 **공개용 키**입니다. 카카오 Developers에서 허용 도메인을 제한하세요. REST API 키는 이 용도로 사용할 수 없습니다.
- `.env`, `.env.local`, 운영 환경 파일은 프로젝트와 상위 작업 폴더의 `.gitignore`에서 제외합니다. 값이 비어 있는 `.env.example`만 커밋할 수 있습니다. `.env.local`이 별도로 있으면 `.env`보다 우선합니다.
- `.env` 변경 후 개발 서버를 재시작합니다. 배포할 때는 호스팅 서비스의 서버 환경변수 설정에 값을 입력하며 파일을 GitHub에 업로드하지 않습니다. 이미 과거에 공개된 키는 `.gitignore` 추가로 회수되지 않으므로 해당 제공처에서 폐기·재발급해야 합니다.

서울시 공식 bikeList 주소는 HTTP 8088 포트를 사용합니다. 공개 샘플의 HTTP 응답을 확인했으나 HTTPS 연결은 확인되지 않았습니다. 인증키를 HTTP로 전송하는 확인 작업은 자동 승인 검토가 차단했습니다. HTTP 전송에 대한 명시적 승인 전까지 `SEOUL_ALLOW_HTTP=false`를 유지합니다. 승인 후 서버 `.env`에서 `SEOUL_ALLOW_HTTP=true`를 설정하고 재시작하면 대여소 실제 조회를 시작합니다(`DATA_MODE=live`는 대여소 조회에 필요하지 않습니다). 키는 브라우저/GitHub에 전달하지 않지만, HTTP 전송 중에는 암호화되지 않습니다.

카카오 SDK를 실제 확인한 결과 `http://127.0.0.1:3000`은 `domain mismatched`(HTTP 401), `http://localhost:3000`은 HTTP 200이었습니다. `localhost`로 접속하거나, 필요한 주소를 Kakao Developers의 SDK 허용 도메인에 추가하세요. 지도 연결 실패는 경로 REST API 권한과 별개입니다.

## 검증

개발 서버를 실행한 상태로 다음을 실행합니다.

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run check:api
npm.cmd run check:routing
npm.cmd run check:accidents
npm.cmd run check:weather
npm.cmd run check:integration
```

단위 검사는 제공처 응답 형태의 테스트 전용 fixture로 대여소·경로·사고 처리, 격자 투영, 발표 주기 경계, KST 날짜/연도 변경, 같은 시각 TMP/POP 결합, 결측값·0 값 처리, 전체 페이지 수집 등을 검사합니다. 테스트 fixture를 앱에서 가져오거나 실패 시 대체 데이터로 사용하지 않습니다. `check:routing`은 공식 예제 좌표로 로컬 경로 API를 통해 두 실제 요청을 실행하며 테스트용 식별자 ST-0을 사용합니다. `check:accidents`는 사고정보 전체와 실제 카카오 경로로 근접 분석을 검증하고, `check:weather`는 출발지 격자와 실제 단기예보·발표/예보시각을 검증합니다. 검사용 좌표가 실제 대여소 선택을 뜻하지 않으며 화면에 테스트 데이터를 주입하지 않습니다.

API 검증 스크립트는 정상·빈 검색 결과, 잘못된 입력, URL/모드 주입 차단, 메서드 제한, 환경 파일의 HTTP 접근 차단, HTML·API 응답·공개 빌드 파일의 서버 키 미포함을 검사합니다. 실제 대여소 응답이 있으면 정렬과 실제 데이터 표시를 검사하고, 차단/실패 상태이면 가상 fallback 없이 오류만 반환하는지 검사하며 실제 조회 성공이 미검증임을 출력합니다. HTTP 전송 승인 후 `EXPECT_LIVE_STATIONS=true`로 실행하면 성공 응답을 필수로 검증합니다. 검사 출력에 키 값을 기록하지 않습니다.
